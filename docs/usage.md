# 使用手册

[English](usage.en.md)

[返回 README](../README.zh-CN.md) · [安装](install.md) · [排查问题](troubleshooting.md)

sub2sub 以任务为单位使用授权共享的 AI 订阅。你在自己的对话里委托任务，共享端使用自己设备上已登录的 Codex 或 Claude Code 处理；文件和答复保存到你本地，后续修改继续同一任务。你无需登录对方账号，也可以在自己的多台设备之间使用同样的流程。

第一次使用，从下面的设置确认和配对开始。已经连好设备，可以直接看[派发和追加需求](#派发和追加需求)。想查看手头的任务与成果，可以打开[本机管理页](#本机管理页与统计)。


跨网络连接服务默认关闭。不同网络设备需要双方主动开启，再照常配对；旧连接保持原方式，可主动迁移。活动任务、成果传输和结果未知的提交会阻止关闭，须先完成或明确取消。[开启、迁移与版本兼容](install.md#跨网络连接)。

## 按连接设置共享规则

共享端可在管理页“我共享的 → 已授权使用端 → 规则”，或在原对话通过 `pairing_settings`，为一个连接设置并发上限与授权截止时间。新旧连接默认不额外限制、不过期，仍受节点总并发限制。留空（工具传 `null`）移除相应限制。

截止时间按本机时区填写；工具使用 UTC 时间。到期后停止新任务和追问执行，已有轮次可以完成，状态查询、取消和成果取回继续可用。任务活动不续期；共享端延长原连接期限即可继续原任务。撤销授权仍会立即断开，重新使用需要重新配对。连接规则不改变工作副本清理和已保存成果。

同一“规则”面板可设置可选的**累计 Token 上限**（`pairing_settings.tokenLimit`，正整数；`null` 表示关闭）。两端都能看到已记录用量、剩余预算和计量缺口。预算属于当前配对连接，不代表真实人员或订阅账号；多个连接、多个 Host 分别计算。

启用预算时，每轮停止后结算一次，失败、取消和超时仍计入已发生用量。达限后拒绝新任务和追问，查询、取消和取回尚未清理的成果继续可用。正在执行的轮次可以完成并产生超额，并发时可能超出更多；不预扣、不因预算在轮中中断、不按周期重置。调低上限不打断工作，调高上限提供更多空间而不清零。删除任务或历史、重启、关闭后重新开启都保留累计；关闭期间开始的轮次和启用前历史不补扣。

Codex 使用原生总 Token，缓存和思考不重复加算。Claude 汇总各模型的输入、缓存读取、缓存写入与输出，思考已包含在输出中。最终统计缺失时保留已知消耗，暂停新执行。共享端确认原执行已经停止后，可在规则中明确接受缺口并恢复（`acceptUsageGap=true`）；不完整标记保留，不把未知 Token 填成零。共享进程异常重启后的恢复遵循相同规则。预算写入失败会停止新接单，需要重新开启共享、恢复待结算记录。

预算与可删除的任务统计分开，只保留累计、缺口状态和在途任务／轮次标识；结算后删除在途标识，不保留正文或文件。预算不是价格，也不是上游账号剩余额度。

Codex 适配沿用此前在 0.153.4 验证的每次原生连接累计口径。主线程事件不覆盖子线程，因此预算轮次在进程与会话配置中关闭 `multi_agent` 和 `multi_agent_v2`，续作也一样。[官方 `multi_agent` 设置](https://developers.openai.com/codex/config-reference/)控制协作工具；本次也用 CLI 0.147.0 的只读 `features list` 确认了两个开关。Claude 使用 SDK 0.3.263 的 `result.modelUsage`，[原生统计包含辅助工作](https://code.claude.com/docs/en/agent-sdk/cost-tracking)，委托工具仍只开放 Bash。本次回归使用模拟原生事件，没有实际模型执行；其他原生版本可能改变或缺失统计，最终观测不完整时暂停预算，不宣称完整覆盖。

成果交付会在原对话简述本轮答复与实际调整，并提供已保存的成果入口和未完成项。管理页复用同一份答复；不额外生成总结或提供 diff。

## 角色与授权

**使用端 Client** 是发起任务并接收成果的设备；**共享端 Host** 是开放 AI 能力、执行授权任务的设备，账号凭据由其所有者保管。同一台设备可以兼任两种角色。目前支持 Codex 和 Claude Code，更多工具支持正在开发中。

共享端生成邀请后，使用端为连接起名。连接成功表示已完成握手；任务文件授权可以在配对时确认，也可以随后通过对话设置。授权覆盖主动委托所需的普通项目材料；凭据、无关文件和需另行确认的敏感材料不属于普通范围。sub2sub 的授权不覆盖 Codex 宿主审批。

邀请码包含连接所需信息，只应私下发给指定使用者；不要放到 README、Issue 或截图中。

新手可在管理页底部打开“使用帮助”，查看邀请、连接、小文件任务和续作例句。首次确认设置前也会简要说明流程；帮助页本身不会开启共享或跨网服务。

## 首次使用

新设备第一次使用时，即使你已经给出明确任务，助手也会先提醒并完整展示当前设置：Codex 与 Claude 的使用端默认模型和思考强度、共享端执行工具及各工具开放模型、双方输入与返回限制、保留期限与清理条件、设备名称与高级路径、已有连接及文件授权、获授权使用端和当前共享状态。确认后再连接、共享或委托，并继续你原先的请求。

可以先要求修改设置，再确认更新后的汇总。尚未设置的 Claude 选项保持未设置；实际模型可用性需在连接节点后查询其当前列表，默认值不代表已经验证可用。查看引导不需要本机安装执行工具，也不会开启共享或执行模型。设置确认不等于任务文件传输授权。

确认或明确跳过只记录一次。中断后会保留设置并继续待确认状态；随时可以说“重新打开首次使用引导”。升级时会识别已有配置、连接或任务与共享记录，保留原设置，不强制老用户重新引导。之后普通设置查询保持简洁，需要时再查看高级设置。

## 派发和追加需求

每轮最长 30 分钟，较长工作可分阶段继续。任务使用独立工作副本，任务网络、MCP、应用和浏览器集成关闭；按任务需要带上输入、依赖声明、锁文件和说明；已安装依赖及凭据不随项目复制。

达到时限时，执行停止，sub2sub 将已有阶段成果保存到本地，说明尚未完成的工作，再等待你决定是否继续同一任务。保存失败时重试取回即可，不需要重新执行任务。执行工具尚未写入文件的内容无法通过回传恢复。

每次交付一起说明当前成果、两端实际完成的检查，以及未完成的工作或检查及其原因。检查随任务而定，例如代码测试、文档核对、数据校验。文件已保存不代表全部要求已完成。

新任务的工作副本包含内部 `.sub2sub` 目录，用来放可丢弃的工具缓存；不回传，随工作副本清理，无需增加设置。必要成果及继续工作所需文件放在该目录以外。旧任务和其他被排除路径保持现有处理方式。

推荐在任务中说清目标、输入范围、产物及验证要求，例如：

> 把 docs 目录交给工作电脑，整理成离线帮助页面。不要联网或安装依赖。请在远端完成实现、相关测试和必要复核，最后返回页面与使用说明。

插件会准备固定的输入快照并展示目标、文件数和体积。默认读取 Git 已跟踪文件的当前内容，包含未提交修改；未跟踪文件需明确选择。依赖目录、常见凭据路径等会被排除；符号链接和特殊文件不作为普通文件传输。

继续说“在刚才的任务中增加……”会沿用远端工作副本和原生会话。已接受任务保持自身模型与保留选项，不受后续默认值变化影响；明确要求时才调整任务模型。

一次完整回合包括执行结束及成果保存。执行失败、中断或超时也可能留有可恢复文件；能下载这些文件不表示执行成功。

## 两端环境不同

共享端在当前任务开头检查任务沙箱中实际可用的工具和依赖，只检查这项任务需要的条件，不做全量环境扫描。无需额外确认或新增全局设置；执行中才暴露的问题按同样规则处理。

| 情况 | 默认处理 |
| --- | --- |
| 环境满足要求，或缺少的工具不影响本次任务 | 继续执行，不打断用户 |
| 可以完成修改，但部分检查无法在共享端运行 | 返回修改和未验证项，由使用端的 Agent 按本地权限和任务授权，在独立的本地验证副本中补充验证 |
| 环境缺口阻碍任务明确要求的共享端运行或验证，或导致无法完成有效工作 | 说明缺口，等待用户选择准备环境、换共享端或调整范围 |
| 使用端也缺少必要的验证环境 | 明确剩余要求，询问如何继续 |

默认允许本地补充验证，但不能替代任务明确要求的共享端验证。环境缺口不授权安装系统依赖、传递凭据或扩大权限。使用端执行前需检查返回的修改和相关脚本，保护源项目及已有改动。分别报告两端实际完成的检查；必需验证通过后才能声称完整完成。

测试、构建、准备依赖等可能写文件的检查，先从已保存文件复制出独立验证目录。插件管理的 `workCopyDirectory`、`resultDirectory` 和任务索引保持原样，用于后续增量取回和恢复。在其中修改文件或生成符号链接，可能混入本地改动或阻断取回；验证产生的文件也不要写回这些保存目录。

本地验证发现原任务范围内的问题时，可以将必要报错交回原任务续作。本地修改不会自动同步到已有远端工作副本。仅查看已保存成果不会重新执行检查。

## 打开和使用成果

保存后的三个入口：

| 字段 | 内容 |
| --- | --- |
| `workCopyDirectory` | 本次完整任务副本，含输入与最新修改 |
| `responseFile` | 本次保存的文字答复 |
| `resultDirectory` | 本次变更文件、`changes.json` 和答复记录 |

让助手展示这些路径对应的本地链接。以后说“查看成果”使用已保存版本，无需远端连接。若新一轮还没保存，路径指向上次结果，不能当作本轮交付。

源工作区不会自动覆盖。检查结果后，由你决定复制、比较或合入源项目。无文件变化的有效同步复用已有完整副本；有变化时建立新的完整副本，之前保存的历史结果仍保留。

回传或保存确认失败时，对同一任务重试收取即可；不要因此重复执行任务。检查 `changes.json` 的 `skipped` 和执行错误，必要产物被跳过时应在原任务补齐。

## 设置与查询

| 对话示例 | 目的 |
| --- | --- |
| “打开 sub2sub 管理页” | 获取本机私密入口；可随时关闭 |
| “查看近 7 天我使用的资源统计” | 查看现存任务的轮数、结果、时长和原生模型用量 |
| “帮我排查办公室节点连接失败” | 复用现有查询，只读排查当前问题 |
| “把这个问题提交到 GitHub” | 整理公开草稿、查重后使用宿主已有提交能力 |
| “查看使用端设置” | 查看默认模型和思考强度 |
| “默认用某模型，思考强度 high” | 仅修改以后新建任务的默认值 |
| “共享端开放全部模型” | 开放账号当前实际可用模型并包含未来新增项 |
| “共享端只开放这两个模型” | 使用明确的提供范围 |
| “共享端切换为 Claude” | 空闲时切换执行工具；失败保留原选择，旧任务保留原工具和会话 |
| “查看办公室节点的剩余额度” | 刷新该节点 Codex 账号的额度窗口、剩余比例和重置时间 |
| “查看高级设置” | 查询传输限制和共享端保留期 |
| “查看可用节点” | 区分可用、忙碌、停止共享或连接失败 |
| “查看本机作为共享端的状态” | 查询实际共享进程、授权连接和任务 |
| “查看委托任务及最新成果” | 查看本地任务索引、创建/结束时间与保存状态 |

使用端按执行工具分别保存一套默认模型与思考强度，跨节点共用。Codex 默认为 GPT-5.6 Luna / max；首次使用 Claude 时，从节点实际提供的选项选择模型和思考强度，可保存为默认值。单次任务可以指定。共享端空闲时可手动切换工具，旧任务需要切回原工具才能续作。

额度来自实际执行节点的订阅账号，每次查询都会刷新；不必为了本机查询开启共享。比例按各窗口分别展示，不相加。缺失数据表示未知，已过重置时间的数据标为过期，查询失败不复用旧数字。Claude 和不支持查询的旧节点会明确说明。配对使用者默认能看到基础额度，不包含账号邮箱或详细历史。额度与可用、忙碌、停止状态分开，不自动分配或拒绝任务。

传输限制与保留期放在高级设置。输入与结果默认不限大小和文件数量；管理页的大小上限以 MiB 输入（支持小数），文件数量以个数输入；工具接口的大小参数仍以字节计，须为正整数。用 `null` 或在管理页留空恢复不限量。双方都设置时采用较小值，一方不限量时遵守另一方设置。已有有限设置及任务已接受的限制保留。

每次实际传输的原始文件总量超过 64 MiB 时提醒可能较慢，尤其是非局域网连接，随后继续，无需额外确认。字节按原始文件计算，不按压缩或 base64 大小。输入限制针对完整工作副本，结果限制针对本次变化；恢复已清理任务时重新检查完整输入。默认不限量不保证任意网络速度或磁盘容量，真实失败会说明原因。

双方需支持分块传输。较旧节点仍受其原有上限约束，传输前会说明限制和升级要求；本机共享进程也需在活动任务结束后重启加载新版。升级不会自动重启活动节点。

共享端保留期为1–365天，默认7天；已接受任务保留当时的期限。查询、下载和 `keep` 不续期，新一轮结束会重新计时。

## 委托会话展示

共享端设置新增「保留委托会话在任务列表中」，也可以说「开启委托会话展示」或「关闭委托会话展示」，修改同一个 `keepSessionVisible` 配置。仅用于 Codex 原生会话；Claude 暂不支持此展示管理，保持原行为。

默认关闭：执行期间会话可能出现在客户端，每轮停止后归档，续作前恢复同一个会话。开启后保留在普通任务列表，方便共享端在执行期间查看进展。设置只影响之后新建的任务；已有任务及其续作沿用创建时模式，升级前的任务保持原行为。首版仅支持查看，不支持从原生客户端追加指令或接手，也不承诺禁用客户端输入框。

归档保留原生历史，不删除成果或延长工作副本保留期。归档失败时显示具体原因，执行状态及成果不因此改变，不要为隐藏会话重跑任务；恢复失败会在新一轮开始前停止。工作副本到期清理后，历史中的远端文件链接可能失效，完整成果仍从使用端本地副本查看。具体客户端与版本的验证范围见 [验证记录](validation.md)。

## 本机管理页与统计

想看看谁在忙、成果存好了没有，在原对话中说“打开 sub2sub 管理页”。页面通过私密本机链接，集中展示节点、任务和已保存成果，也能配对、调整设置、按需查询模型和额度。任务指令和追问仍在原对话中完成。已保存答复及文件可在共享端离线时预览或下载；页面不会执行成果中的 HTML 或脚本。

管理页默认开启，仅监听 `127.0.0.1` 的随机端口，不自动打开浏览器。设置中可随时关闭，也可在对话中说“关闭网页管理”；关闭选项会保存在 sub2sub 自有配置中。之后说“重新启用网页管理”即可恢复。每个 MCP 进程拥有自己的临时链接，完整退出该宿主进程后失效；已打开的其他进程入口在下一次请求时停止提供数据。独立共享节点不受影响，不需要为网页增加常驻进程。

页面未打开时不轮询；总览可见时每 30 秒读取本机记录，隐藏页面后暂停。远端在线状态由“刷新状态”主动检查，模型与额度仅点击时查询，保留采集时间。查询失败或额度窗口过期不会当作当前可用额度。

“我使用的”与“我共享的”分别按资源及执行工具汇总近 7 天或 30 天的任务数、轮数、结果状态和已测执行时长。窗口按轮次开始时间计算，从本版新增的轮次开始计量；旧轮次和未知时长不会推算。使用端只统计已收到的执行或成果记录，并非共享端全部历史；刷新和重复下载不新增轮数。清理工作副本保留统计，明确删除任务记录时删除该侧相应统计，本地已保存成果继续保留。统计不等于账号额度、费用或质量评价。

模型用量按实际模型和原生来源分组，可展开逐轮明细并导出 JSON。请求模型与实际模型分开；未知值显示“—”，部分记录、覆盖轮数和待同步任务均会注明。任务详情可查看该任务保留的全部轮次，不受概览的时间窗口限制。Codex 的缓存读取包含在输入中、推理包含在输出中；Claude 输入、缓存读取和缓存写入按原生字段分别展示。不把分类再次相加，也不补算缺失的总计。双方视图描述同一份消耗，不能叠加。

节点并发上限在共享端普通设置中调整，默认 4。同一使用端可占满全部名额，同一任务不能同时执行两轮；调低上限让已有任务完成，空出的名额满足新上限后再接单，无需重启。

遇到问题，可从页面“问题排查”回到原对话，让助手复用已有状态查询。明确要求提交 GitHub 后，助手整理适合公开的内容、搜索重复问题并通过宿主已有能力提交；不可提交时提供草稿。不要公开邀请码、管理页私密链接、凭据、个人路径或原始私有任务内容。

## 任务生命周期

1. **首次执行**：上传选定工作副本，创建原生会话。
2. **阶段保存**：接收文件变化，在本地形成完整副本并确认保存。
3. **继续工作**：复用远端副本和原生会话。
4. **结束或到期**：满足成果已保存且执行停止等条件后，按选择清理。
5. **清理工作副本后续做**：重新上传已保存的完整副本，恢复原会话。

| 选择 | 含义 |
| --- | --- |
| `keep` | 沿用当前期限，不增加期限 |
| `workcopy` | 删除远端工作文件及传输载荷，保留恢复信息与原生历史 |
| `records` | 另删sub2sub任务记录，不再自动恢复 |
| `all` | 另删对应原生会话及子会话 |

默认到期清理仅处理远端工作副本。最新必要成果未保存、状态未知、执行活动或清理失败时会保留并报告原因。检查在共享进程运行时执行；设备离线时不承诺定时删除。

本机源文件、完整副本、历史下载和索引不属于远端清理范围。共享的原生诊断日志、系统备份与服务侧留存也不在插件清理范围内。

## 连接和共享端管理

重命名连接不影响任务。同一设备换IP时，可以更新地址并验证原设备身份；更换设备需要新配对。

删除连接前先处理关联的执行中任务及未取回成果。删除后重新配对不能恢复旧任务的连接关联。本地保存的成果仍可查看。

共享端可停止接收新任务，也可以撤销指定使用端；撤销会中断该使用端的活动任务。共享端还可单独清理已停止任务；若存在未取回成果，必须明确决定是否丢弃。

## 自有数据目录

- 配置默认位于 `~/.config/sub2sub/config.json`，可用 `SUB2SUB_CONFIG` 指定。
- 状态默认位于 `~/.local/state/sub2sub`，可在自有配置的 `stateRoot` 中指定绝对路径。
- Windows 中 `~` 指当前用户的主目录。
- 配对凭据、共享身份与任务副本在这些目录中；不要公开整个目录。

初次使用会按需建立自有配置，不必手工编辑。程序示例见仓库的 `config.example.json`；它只用于理解配置形态，应替换示例绝对路径，不能照抄另一台设备的配置。

## 设备名称与本地空间

在原对话中说“把这台设备在 sub2sub 中改名为办公室 Mac”，或在管理页的设置中修改设备名称。改名只影响 sub2sub；已配对设备在后续通信时同步，同名自动加编号。连接时可以留空别名以跟随设备名称，手动设置的别名会保留。

说“查看 sub2sub 的本地空间占用”，或进入管理页“设置 → 本地空间”，可以查看任务记录、输入快照、答复与成果、完整副本的占用，并区分旧成果和当前文件。共享目录在总计中只计算一次；显示的是文件字节数，实际释放的磁盘空间可能不同。

清理前会显示文件范围、预计删除大小和影响。可以只清理旧成果，也可以清理全部本地文件，并选择是否一并删除任务记录及对应统计。此版本清理全部本地文件后无法继续或重新取回该任务，需要时从原始输入新建任务；源项目、远端数据及原生客户端历史不受影响。仅清理文件时仍保留任务记录，并显示“本地文件已清理”。首版不自动清理本地数据。共享端工作副本沿用现有清理流程和保留期。
