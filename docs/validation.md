- Claude Code 2.1.104 通过临时 MCP 和 Skill 接入完成两轮简单文件任务：生成 `answer.txt`，再修改为新内容；两轮均主动取回并读取本地文件和答复，同一原生会话得到核对，最终测试工作文件、记录和原生历史已清理。模型为 GPT-5.6 Luna / low，连接为本机 TLS。0.5.2 安装器仅面向 Codex；该轮不覆盖 Claude 长等待、取消 UI 或其他 Claude 产品。

## 复杂任务体验

在Windows上用同一原生会话完成一个无外部依赖的离线排程应用，再追加工作日历与撤销重做。提供方报告36项**应用自身**测试通过并完成独立复核；这36项不是sub2sub插件回归测试。

同时观察到：

- 第一阶段触发30分钟固定上限；原任务恢复成功，未丢失工作文件。
- 第二阶段继续同一任务及会话，新增功能后完成增量回传。
- 浏览器临时profile导致结果超过20MiB，任务沙箱拒绝删除；最后在单次宿主审批后清理，正式LAN回传成功。因此不能称为全程无干预。
- 标准目录中存在Chrome/Edge，但受限执行中出现GPU初始化失败；没有有效页面截图和动态DOM结果，浏览器交互未验收。

最终已保存完整源码、测试和说明，无跳过的必要输出。上述记录只说明这次流程的实际表现，不证明任意复杂任务都能自动完成。

## 自行验证

macOS/POSIX环境：

```sh
npm run check
npm test
```

Windows聚焦平台行为：

```powershell
node --test test/platform.test.mjs
```

真实订阅生命周期冒烟测试需明确授权后执行：

```sh
node scripts/lifecycle-smoke.mjs /absolute/path/to/codex
```

该命令实际使用提供方登录的订阅，执行两轮合成任务、清理工作文件并验证同会话恢复，最后删除该测试的原生历史。它不是普通单元测试，不在CI中自动执行。
