## 0.5 系列安装与 CLI

- macOS 完整源码回归 73 项通过，语法检查通过。最终 0.5.1 的[五个 CI 检查](https://github.com/mekoand/sub2sub/actions/runs/34042004850)全部通过：macOS / Linux 各运行 Node 22、24 完整套件，Windows 单独运行 6 项平台测试。[自动打包流程](https://github.com/mekoand/sub2sub/actions/runs/34042014862)成功生成三个平台的发行包。
- macOS Apple Silicon 和 Windows x64 实际运行公开 GitHub 安装脚本，完成下载、校验和原生插件安装，确认 `sub2sub@sub2sub` 0.5.1 已安装并启用。两端同版本重复安装通过，Windows 另验证了从 0.5.0 升级到 0.5.1。测试使用独立程序目录和 Codex 配置目录。
- macOS Codex CLI 使用实际安装的插件，向独立提供方进程派发文件处理任务，再从另一次 CLI 调用继续同一任务。回传文件内容核对通过，最终删除了测试的远端工作文件、记录和原生会话。本次使用本机 TLS 连接；此前双机验证记录见下文。
- macOS 真实任务中运行随包 Node，完成读取输入、生成 JSON 和回传，核对运行时为 `v24.20.0`。任务只额外获得该 Node 可执行文件的读取权限。
- 新增测试覆盖安装、重复安装、启动路径刷新、旧来源迁移、安装失败后重试，以及不依赖 PATH 中 OpenSSL 的证书生成和身份复用。Tailscale 地址测试覆盖 `100.64.0.0/10` 及相邻无效范围。
- Tailscale 实际跨网络配对、任务执行与回传留到后续版本验证。Claude、WorkBuddy 等其他 harness 尚未实测。

公开安装测试发现 macOS 临时目录的路径别名会让安装入口被跳过；0.5.1 已修复，并通过实际符号链接启动脚本的回归测试覆盖。CI 中固定等待后过早关闭 MCP 客户端的测试，也已改为等待真实响应。

已有实测覆盖：默认配置缺失时邀请/TLS配对、身份复用、失败后重试、真实原生会话两轮续做、工作副本清理后恢复、最终记录/会话清理。Windows独立平台测试4项通过；历史macOS完整源码回归65项通过。发布后的CI结果以仓库Actions实际记录为准，不把历史次数当成跨平台保证。

## 复杂任务体验

在Windows上用同一原生会话完成一个无外部依赖的离线排程应用，再追加工作日历与撤销重做。提供方报告36项**应用自身**测试通过并完成独立复核；这36项不是sub2sub插件回归测试。

同时观察到：

- 第一阶段触发30分钟固定上限；原任务恢复成功，未丢失工作文件。
- 第二阶段继续同一任务及会话，新增功能后完成增量回传。
- 浏览器临时profile导致结果超过20MiB，任务沙箱拒绝删除；最后在单次宿主审批后清理，正式LAN回传成功。因此不能称为全程无干预。
- 标准目录中存在Chrome/Edge，但受限执行中出现GPU初始化失败；没有有效页面截图和动态DOM结果，浏览器交互未验收。

最终已保存完整源码、测试和说明，无跳过的必要输出。上述记录只说明这次流程的实际表现，不证明任意复杂任务都能自动完成。

## 自行验证

macOS/POSIX环境：

```sh
npm run check
npm test
```

Windows聚焦平台行为：

```powershell
node --test test/platform.test.mjs
```

真实订阅生命周期冒烟测试需明确授权后执行：

```sh
node scripts/lifecycle-smoke.mjs /absolute/path/to/codex
```

该命令实际使用提供方登录的订阅，执行两轮合成任务、清理工作文件并验证同会话恢复，最后删除该测试的原生历史。它不是普通单元测试，不在CI中自动执行。
