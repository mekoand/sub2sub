# 故障排查

[English](troubleshooting.en.md)

[返回 README](../README.zh-CN.md) · [安装指南](install.md)

先确认两端的插件版本、Node/Codex版本和实际运行路径。提供诊断时移除邀请码、token、个人路径和项目内容。

| 现象 | 下一步 |
| --- | --- |
| 配对后 `ECONNREFUSED` | 提供方可能已关闭承载共享的进程。重新开启共享，复用原配对；不要先删连接 |
| 连接超时 | 检查选定IPv4地址、网络可达性、设备休眠和所选端口的入站许可 |
| 邀请无效或过期 | 邀请仅用一次、10分钟有效，新邀请会替换旧邀请；让提供方重新生成 |
| 节点忙碌 | 一个提供方同时只接受一个活动任务，先查询原任务状态 |
| 模型或强度不支持 | 从返回的实际可选组合选择；配对成功不代表模型开放或余额足够 |
| `Turn exceeded 30 minutes` | 查询原任务，必要时先保存恢复文件，再继续同一任务；拆分后续阶段 |
| 结果超过20MiB或文件数上限 | 整理本次任务生成的无用临时产物，或明确调整双方高级限制；保留必要成果 |
| 结果保存确认失败 | 重试同一任务的 `collect_result`，不要新建重复任务 |
| 清理被拒绝 | 检查未保存成果、活动状态、实际文件权限及宿主提示，不默认增加权限 |
| Windows找不到原生Codex | 用实际 `codex.exe`，不能把npm的 `.cmd` / `.bat` 配为提供方可执行文件 |
| Windows共享生成证书失败 | 升级双方到0.5；安装包自带证书生成，不再需要外部 OpenSSL。保留底层错误便于定位 |
| Windows沙箱初始化失败 | 从已登录的桌面会话运行；SSH系统会话是已观察到的限制场景 |
| 浏览器命令找不到 | 检查标准安装位置，不能只凭PATH判断不存在；存在也不表示受限任务能成功调用 |
| 新安装版本没有生效 | 确认安装缓存已更新，并开启新Codex对话；源码目录变化不会更新已有进程 |

## 任务失败时怎样继续

执行失败与成果回传失败是两回事。先查询状态，确认是否仍有活动执行；停止的失败任务可能保存了可恢复文件。下载并检查这些文件后，再在原任务续接。

如果仅回传失败，先修复回传问题并重试，不自动重新执行。原生历史已删除、本地恢复文件缺失或更新成果被明确丢弃时，应接受返回的恢复限制，不用新任务冒充原会话恢复。

## 浏览器和临时文件

任务关闭了内置浏览器、应用和网络集成。即使设备装有浏览器，通过命令启动也可能受系统沙箱或GPU环境影响；没有有效页面结果就不能标记浏览器验收通过。

真实复杂任务中出现过浏览器profile使一个小工程超过默认回传上限，且任务内删除被宿主策略拒绝。任务应把临时数据与正式成果分开并在交付前检查；当前版本尚不能保证所有此类收尾无需人工介入。不要把整个浏览器个人资料目录当成成果，也不要通过关闭沙箱解决。

## 提交一个可用的问题报告

请在[GitHub Issues](https://github.com/mekoand/sub2sub/issues)中提供：

- 系统、插件版本、Node/Codex版本（与问题相关时）。
- 发生在哪一步：安装、邀请、配对、执行、回传、续做或清理。
- 最小复现步骤、预期行为与实际错误。
- 已脱敏的实际程序路径和任务状态，是否仍在运行、最新成果是否保存。

不要提交邀请码、配对token、登录信息、完整config或state目录。
